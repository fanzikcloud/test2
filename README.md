# Fanzik Client

Клиентский Minecraft-мод для **Minecraft 1.21.1 · Fabric · Java 21**, рассчитанный на Windows и Linux. На сервер устанавливать мод не нужно. Он работает и в одиночном мире, и при подключении к серверу.

## Возможности

- Меню на **правый Shift**, переназначаемый в `Настройки → Управление → Fanzik Client`.
- Пять категорий: **Combat, Movement, Render, Player, Misc**.
- Один настоящий модуль — **Auto Sprint** в Movement. Остальные категории намеренно пустые.
- Собственная геометрия интерфейса: сглаженные скругления, градиенты, обводки, тени, векторные иконки, анимации, всплывающие подсказки и уведомления.
- Шрифт Roboto с кириллицей, английская и русская локализации.
- Поиск по модулям, назначение клавиш, числовые ползунки, логические и перечислимые настройки, три акцентных палитры.
- Перемещаемое окно с адаптацией к разрешению и масштабу GUI. Меню не ставит одиночную игру на паузу.
- Именованные JSON-конфиги и автоматическое восстановление последнего состояния.
- Локальные команды с точкой и дополнением по **Tab / Shift+Tab**. Команды с точкой, включая неизвестные и ошибочные, не уходят на сервер.
- Расширяемая система модулей, настроек, событий и 2D/3D-рендера.

## Установка

1. Установите **Minecraft 1.21.1** и **Fabric Loader 0.16.14 или новее** для этой версии игры.
2. Установите **Fabric API 0.116.7+1.21.1 или новее, предназначенный именно для 1.21.1**.
3. Соберите проект или скачайте `fanzik-client-1.21.1` из артефактов успешной сборки GitHub Actions.
4. Поместите `fanzik-client-1.0.0.jar` и Fabric API в папку `mods` вашего игрового профиля.
5. Запустите игру на **Java 21**, войдите в мир или на сервер и нажмите **Right Shift**.

`*-sources.jar` — исходники, а не устанавливаемый мод. Forge, NeoForge, другие версии Minecraft и Java 17 не поддерживаются.

Соблюдайте правила конкретного сервера: клиентский Auto Sprint может быть запрещён его администрацией. Обход античита в моде не реализуется.

## Управление

| Действие | Управление |
| --- | --- |
| Открыть / закрыть меню | Right Shift, либо назначенная клавиша меню |
| Закрыть окно / отменить ввод | Escape |
| Найти модуль | Поле поиска или Ctrl+F; поиск охватывает все категории |
| Выбрать модуль | ЛКМ по карточке или ПКМ |
| Включить модуль | Переключатель на карточке |
| Изменить Boolean | ЛКМ по строке настройки |
| Изменить Enum | ЛКМ вперёд / ПКМ назад |
| Изменить число | Нажать или перетащить ползунок |
| Назначить клавишу | Нажать поле клавиши, затем нужную клавишу |
| Удалить привязку | Backspace / Delete во время назначения |
| Переместить окно | Перетащить область логотипа или свободную часть заголовка |
| Выбрать акцент | Цветные точки внизу боковой панели |
| Открыть конфиги | Кнопка «Конфиги» в заголовке |
| Дополнить локальную команду | Tab; Shift+Tab перебирает в обратном порядке |

Клавиша меню зарезервирована и не назначается модулю. В чате и других экранах привязки модулей не срабатывают. Если открыта панель конфигов, первое нажатие Escape / клавиши меню закрывает панель; следующее закрывает меню. При назначении клавиши Escape / клавиша меню сначала отменяет назначение.

## Auto Sprint

По умолчанию выключен. После включения запускает спринт при достаточном вводе движения вперёд и проверяет голод, приседание, столкновения, слепоту, езду, полёт и нахождение в воде/лаве. Не симулирует зажатие клавиши спринта. При отключении снимает только спринт, которым управлял сам; нажатая вручную клавиша спринта имеет приоритет.

Настройки:

- **Пауза в меню** — по умолчанию включена.
- **Пауза с предметом** — по умолчанию включена.
- **Начало спринта** — обычное или только на земле. Уже начатый спринт сохраняется в прыжке.
- **Порог ввода** — от `0.1` до `1.0`, шаг `0.05`, по умолчанию `0.8`.

## Локальные команды

Вводятся в обычном чате **без `/`**:

```text
.help
.cfg save fanzik
.cfg load fanzik
.cfg list
.cfg dir
.toggle auto-sprint
.toggle auto-sprint on
.toggle auto-sprint off
.bind auto-sprint r
.bind auto-sprint right.control
.bind auto-sprint none
.modules
```

Псевдонимы: `.h`, `.config`, `.t`, `.b`, `.mods`. Идентификатор `autosprint` также распознаётся. Команды и имена клавиш нечувствительны к регистру. В `.cfg list` можно нажать имя, чтобы подставить команду загрузки.

## Конфиги

Пути относительно папки **конкретного игрового профиля**, а не обязательно стандартной `.minecraft`:

```text
config/fanzik/
├── state.json
└── configs/
    ├── fanzik.json
    └── another-profile.json
```

- Сохраняются включённость модулей, клавиши, все настройки, палитра, категория и относительное положение окна.
- Изменения автоматически сохраняются с задержкой 750 мс; состояние также сохраняется при отключении от сервера и завершении клиента.
- Файловые операции выполняются в отдельной очереди. Загруженное состояние применяется на клиентском потоке.
- `.cfg save` заменяет одноимённый профиль. Запись идёт через временный файл с `fsync` и атомарной заменой, если файловая система её поддерживает.
- Имена: 1–48 латинских букв, цифр, `-`, `_`; первый символ — буква или цифра. Имена приводятся к нижнему регистру для переносимости между Windows и Linux.
- `..`, разделители путей, расширения и зарезервированные Windows-имена (`CON`, `NUL`, `COM1`, `LPT1` и другие) отклоняются. Символические ссылки на файлы конфигов не читаются и не перезаписываются.
- Лимит файла — 1 MiB. Некорректная схема, типы и значения отклоняются **до изменения модулей**. Неизвестные модули и настройки пропускаются с отчётом.
- При ошибке во время применения выполняется откат. Отсутствующие в профиле зарегистрированные модули возвращаются к своим значениям по умолчанию.
- Повреждённый `state.json` сохраняется как `state.invalid-<время>.json` для восстановления.
- `.cfg dir` использует `explorer.exe` на Windows и `xdg-open` с запасным `gio open` на Linux, без командной оболочки. В Linux нужен графический сеанс и один из этих файловых менеджеров. При невозможности открытия путь остаётся в чате.

Не изменяйте `state.json` при запущенной игре: очередное автосохранение его перезапишет. Для переноса между ОС используйте файлы из `configs`.

## Сборка

Нужен **JDK 21** с компилятором, не только JRE. Gradle устанавливается обёрткой автоматически. Для первой сборки необходим доступ к Maven Central, Fabric Maven и серверам Minecraft.

### Windows, PowerShell

```powershell
.\gradlew.bat clean build
```

### Linux

```sh
chmod +x gradlew
./gradlew clean build
```

Результат: `build/libs/fanzik-client-1.0.0.jar`.

Запуск среды разработки:

```sh
./gradlew runClient
```

Только unit-тесты:

```sh
./gradlew test
```

Настоящий клиентский smoke-тест на Linux с Mesa / Xvfb:

```sh
LIBGL_ALWAYS_SOFTWARE=true ALSOFT_DRIVERS=null xvfb-run -a -s '-screen 0 1280x720x24' ./gradlew runSmokeClient
```

Он создаёт отдельный плоский мир в `build/smoke-run`, проверяет Auto Sprint, клавиши, команды, конфиги, меню, масштаб GUI, реальный 2D/3D-рендер и сохраняет скриншоты. Тестовый entrypoint находится в отдельном source set и **не попадает в устанавливаемый JAR**. Повторный smoke-прогон следует запускать после удаления `build/smoke-run` или `clean`.

GitHub Actions собирает и запускает unit-тесты на **Windows и Linux**, а на Linux дополнительно запускает клиент с виртуальным дисплеем. JAR, отчёты, клиентский лог и скриншоты доступны в артефактах workflow. Отдельная проверка требует наличие отчётов и результата smoke-теста, проверяет состав JAR и remapping production-mixin, чтобы успешное завершение процесса само по себе не считалось доказательством проверки.

```text
src/main/java/dev/fanzik/client/
├── command/    Реестр команд, токенизация, дополнение
├── config/     Независимые снимки состояния, JSON-кодек, файловое хранилище
├── event/      Типизированная шина, приоритеты, управляемые подписки
├── module/     Категории
├── render/     Палитры
├── setting/    BooleanSetting, NumberSetting, EnumSetting
└── util/       Цвета, ошибки, открытие папок

src/client/java/dev/fanzik/client/
├── FanzikClient.java
├── command/    Регистрация игровых команд и локальный вывод
├── config/     Асинхронный сервис и настройки интерфейса
├── event/      Tick, key, session, HUD, world render
├── input/      Имена клавиш
├── mixin/      Клавиша меню, события клавиатуры, Tab в чате
├── module/     Жизненный цикл, реестр, транзакционное применение состояния
├── module/impl/AutoSprint.java
├── render/     Render2D, Render3D, RenderState, Icons
└── ui/         Меню, контролы, конфиги, уведомления
```

### Добавление модуля

1. Создайте класс-наследник `dev.fanzik.client.module.Module` в клиентском source set.
2. Передайте конструктору `MinecraftClient`, `EventBus`, уникальный постоянный `id`, ключи локализации и `Category`.
3. Создавайте настройки через `add(new BooleanSetting(...))`, `add(new NumberSetting(...))`, `add(new EnumSetting<>(...))`. Они автоматически появятся в GUI и конфиге. `visibleWhen` позволяет делать зависимые настройки.
4. В `onEnable` подпишитесь через `listen(ClientTickEvent.class, ...)`, `listen(HudRenderEvent.class, ...)` или `listen(WorldRenderEvent.class, ...)`. Подписки автоматически снимаются при отключении. В `onDisable` освободите изменённое игровое состояние.
5. Зарегистрируйте экземпляр через `modules.register(...)` в `FanzikClient` **до** `configs.restore()`.
6. Добавьте строки в `assets/fanzik/lang/en_us.json` и `ru_ru.json`.

Меню, поиск, категории, команды, сохранение и загрузка используют реестр; отдельно подключать новый модуль к ним не нужно. Исключение в обработчике модуля отключает его и снимает его подписки, не ломая обработчики остальных модулей.

### 2D-рендер

В `HudRenderEvent` доступен `event.renderer()`:

- `rect`, `gradient`, `rounded`, `roundedGradient`, `stroke`, `shadow`;
- `circle`, `arc`, `line`;
- `text`, `centered`, `paragraph`, `elide`, `textWidth`;
- `transform`, `opacity`, `scissor` возвращают область `AutoCloseable` для `try-with-resources`.

Координаты — масштабированные GUI-пиксели, цвета — `0xAARRGGBB`. Геометрия записывается в GUI vertex consumers, а текст использует собственный font resource. Scissor учитывает текущий перенос, масштаб и вложенные области.

### 3D-рендер

В `WorldRenderEvent` доступен `event.renderer()`:

- `quad`, `line`, `polyline`, `filledBox`, `wireBox`, `box`, `circle`, `billboard`;
- `DepthMode.TESTED` — обычная проверка глубины;
- `DepthMode.THROUGH_WALLS` — проход без проверки глубины.

Передавайте **мировые координаты**; смещение камеры и матрица вида применяются внутри. Толщина линий задаётся в мировых единицах. Геометрия буферизуется по проходам и отправляется на GPU после обработчиков. Blend, cull, depth test, depth mask, shader и shader color восстанавливаются. Запись в depth buffer выключена, чтобы не повредить последующий рендер игры. Пример реального использования всех проходов есть в `FanzikSmokeClient`.

Не закрывайте рендерер события самостоятельно и не храните его между кадрами. OpenGL-операции и изменение модулей должны выполняться на клиентском потоке.

### Команды и события

`CommandDispatcher.register(new ClientCommand(...))` подключает команду, её псевдонимы и поставщик дополнений. Поставщик получает уже разделённые аргументы. Обработчик получает список аргументов без имени команды. `IllegalArgumentException` выводится как ошибка ввода, прочие ошибки логируются.

`EventBus.subscribe(type, priority, listener)` возвращает `Subscription`; больший приоритет вызывается раньше. Для модулей используйте `listen`, чтобы подписка была связана с их жизненным циклом. Непривязанные к модулю подписки нужно закрывать самостоятельно.
